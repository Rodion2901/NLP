# Классификатор банковских обращений

Простая классификация: одному обращению соответствует одна категория. Python 3.11+.
Используется sklearn Pipeline: TfidfVectorizer → LinearSVC.

## Запуск

Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m bank_classifier.train --data data/demo.csv
python -m bank_classifier.predict "Потерял банковскую карту" "Хочу погасить кредит"
python -m unittest discover -s tests -v
```

Если есть requirements.lock.txt, точные версии проверенного окружения можно установить
через `python -m pip install -r requirements.lock.txt`.

## Данные

`data/demo.csv` — вручную составленный синтетический пример: 48 уникальных
русскоязычных обращений, 4 класса и один дубль для проверки очистки.
Классы: cards (карты), loans (кредиты), transfers (переводы), deposits (вклады).
Этот файл предназначен для проверки работоспособности. Его метрики не доказывают
качество классификатора на реальных банковских обращениях.
Внешний датасет автоматически не скачивается.

Для своих данных подготовьте CSV UTF-8 с заголовком `text,label`:

```csv
text,label
Хочу заблокировать карту,cards
Как погасить кредит,loans
```

Этот фрагмент показывает формат; для обучения нужны минимум два уникальных текста
на класс и достаточно строк для присутствия всех классов в обеих частях выборки.
Пример команды: `python -m bank_classifier.train --data data/appeals.csv`.
Дополнительно доступны `--test-size 0.2`, `--seed 42`, `--models-dir`, `--reports-dir`.
Пути к данным отсчитываются от текущей папки; стандартные пути артефактов — от корня проекта.

## Архитектура и движение данных

```text
bank_classifier/
  data.py       загрузка CSV, проверка, очистка и удаление дублей
  train.py      разделение, обучение Pipeline, оценка и сохранение
  predict.py    Classifier для Python и командная строка
 data/demo.csv  демонстрационный датасет
 models/pipeline.joblib       появляется после обучения
 reports/metrics.json        метрики, параметры, версии и SHA-256 датасета
 reports/test_predictions.csv  тексты test, истинные и предсказанные метки
 tests/test_workflow.py       проверка обучения, сохранения, инференса и утечки
 requirements.txt            диапазоны зависимостей
```

CSV → нормализация регистра и пробелов → удаление пустых/невалидных строк →
проверка конфликтующих меток → удаление одинаковых текстов → стратифицированное
разделение 80/20 с seed=42 → обучение TF-IDF и LinearSVC только на train →
предсказания для test → accuracy, macro-F1, отчёт по классам и матрица ошибок →
сохранение всего Pipeline в models/pipeline.joblib.

Инференс: новый текст → та же нормализация → сохранённый TF-IDF.transform →
сохранённый LinearSVC.predict → строковая категория. Обучения на этом этапе нет.
LabelEncoder не нужен: LinearSVC принимает строковые метки.
Модель, которая оценена на test, и сохраняется; автоматического дообучения на test нет.

```python
from bank_classifier.predict import Classifier

classifier = Classifier()  # Загружается один раз при запуске приложения.
labels = classifier.predict(["Хочу погасить кредит", "Как открыть вклад"])
```

Три модуля разделяют разные обязанности без сервера, базы данных и конфигурационных
фреймворков. `class_weight="balanced"` компенсирует дисбаланс классов при обучении;
macro-F1 позволяет видеть качество с одинаковым весом для каждой категории.
TF-IDF использует слова и пары слов; лемматизация для первой версии не требуется.

## Границы первой версии

- Совпадение текстов проверяется после приведения регистра и пробелов. Близкие
  перефразировки, цепочки сообщений и обращения одного клиента могут требовать
  группового разделения; для оценки будущих обращений может понадобиться временной test.
- При подборе параметров используйте кросс-валидацию на train, сохраняя test для финальной оценки.
- LinearSVC возвращает класс без вероятности. Для незнакомых тем он может выбрать
  ошибочную категорию. Пустые тексты и тексты без известных слов явно отклоняются,
  но это не полноценное распознавание неизвестных тем.
- joblib загружайте только из доверенного источника; используйте те же версии
  библиотек, что при обучении (они записаны в metrics.json).
- Повторное обучение перезаписывает артефакты в выбранных папках.
  test_predictions.csv содержит исходные нормализованные тексты; учитывайте это
  при работе с персональными данными. Данные и артефакты исключены из Git,
  кроме демонстрационного CSV.

В этой среде PyPI был недоступен, поэтому зависимости в `.venv` скопированы
из уже установленного локального окружения. Их версии зафиксированы в
`requirements.lock.txt`. Окружение проекта автономно; исходное окружение не изменялось.

## HTTP API на Rust

Из корня проекта запустите:

```bash
cargo run --manifest-path api/Cargo.toml
```

Сервис использует существующий `models/pipeline.joblib` и Python с зависимостями
из `requirements.lock.txt`. По умолчанию он выбирает `venv/bin/python`, если
тот существует, иначе использует `python3`. Другой интерпретатор можно указать
через `BANK_API_PYTHON`, например `BANK_API_PYTHON="$PWD/.venv/bin/python"`.

```bash
curl --fail-with-body http://127.0.0.1:3000/predict \
  -H 'Content-Type: text/plain; charset=utf-8' \
  --data-binary 'Не могу войти в приложение банка'
```

`POST /predict` принимает до 64 КиБ текста в UTF-8 и возвращает категорию
обычным текстом, например `cards`. Сервис загружает модель один раз и вызывает
существующий `Classifier.predict` с его нормализацией и TF-IDF. Перед отправкой
успешного ответа репозиторий сохраняет исходный текст и категорию в таблицу
`predictions`. Поле `id INTEGER PRIMARY KEY` автоматически присваивает
уникальный номер записи и позволяет искать по нему.

Пустой запрос, невалидный UTF-8 и текст без слов из словаря модели дают
`400`. Запрос больше лимита даёт `413`. Ошибка модели или записи в SQLite
даёт `500`.

Адрес задаётся через `BANK_API_ADDR` (по умолчанию `127.0.0.1:3000`),
путь к БД — через `BANK_API_DB` (по умолчанию `api/predictions.sqlite3`).
